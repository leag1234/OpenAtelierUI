# Current access-grant compatibility slice

This BSD-3-Clause slice follows behavior-only black-box observations of current Open WebUI 0.12.4. It uses the old runtime's existing `access_control` JSON column; it introduces no schema, dependency, route permission default, or durable grant-history representation.

Creation with omitted/null/empty `access_grants` is private (`{}`). Obsolete request `access_control` extras are ignored so an old public-read ACL cannot broaden a current private create. One `{principal_type: "user", principal_id: <id>, permission: "read"}` grant maps to legacy `read.user_ids`; the sole user `*` read grant maps to the old public-read value (`None`), which still requires an authenticated user through the existing verified-user route dependencies. Group grants, write grants, malformed grant structures, blank IDs, duplicate grants, mixed public and targeted grants, and unsupported grant fields fail validation before the tool module is loaded or data is changed.

Ordinary tool and model edits restore the existing ACL after form validation, whether the edit omits grants, sends null/empty grants, or attempts a different nonempty grant. This matches the measured 0.12.4 behavior; the older 0.12.3 probe applied nonempty replacement grants, so that version's behavior is a known conflicting regression and is not claimed compatible. Rights changes use owner/admin-only dedicated access-update routes. They accept a list (including `[]` to clear); null or missing values fail with 422. Member/unrelated access updates fail with the observed tool 401 and model 400, and the stored ACL is unchanged. Optional model `name` in the dedicated payload is ignored, matching observation.

For an authorized tool read, owner/admin responses retain source and specs. Read-only direct tool responses include specs and omit the `content` key; list responses include specs and `content: null`. Model read responses include the allowed model fields. Both resource types return `access_grants` metadata and `write_access`. An authenticated model reader denial returns 401; missing model also returns 401. Existing authentication dependencies remain responsible for anonymous requests.

Grant metadata is reconstructed from the legacy ACL and resource row. `id` is a deterministic opaque compatibility identifier, `resource_type` and `resource_id` identify the row, and `created_at` uses the resource creation timestamp. Incoming server metadata fields are accepted for round-trip but are never used as authority. Current replaces opaque grant IDs and grant timestamps when rights change; the old single ACL column cannot represent that event history. Exact grant IDs/timestamps, version IDs, history, audit semantics, group/write behavior, and every response/detail shape are therefore unqualified. This implementation intentionally does not fabricate grant or resource-version history.

`python3 backend/open_webui/test/test_explicit_access_grants.py` runs eight named dependency-light tests against the actual `ToolForm` and `ModelForm` class definitions extracted verbatim from the checked-in model modules and the real helper. They cover private defaults, ignored obsolete ACL extras, targeted/public read conversion, malformed and unsupported grants, ordinary-update ACL preservation, metadata projection/round-trip, and caller-data immutability. `PYTHONPYCACHEPREFIX=/tmp/openatelier-current-rights-pycache python3 -m py_compile ...` and `git diff --check` passed during source review. No application dependencies were installed. Primary-owned pinned-runtime API, authorization, source-projection, current-client and regression checks are the evidence for routes; this source-only test does not run FastAPI or SQLAlchemy and does not establish a full 0.12.4 compatibility or security certification.
