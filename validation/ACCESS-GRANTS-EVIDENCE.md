# Explicit access grant form compatibility

This bounded correction handles only the explicit `access_grants` input on the existing `ToolForm` and `ModelForm`. A shared BSD-3-Clause helper runs as a Pydantic before-validator for those two forms only. An explicitly present `null` or empty list becomes the old private ACL `{}`. Every nonempty grants list is rejected with an actionable validation error because the old runtime cannot preserve the measured per-principal content/source rights. Non-list values and simultaneous `access_grants` plus `access_control` also fail validation. The conversion copies the caller mapping and does not mutate supplied values. The forms do not serialize `access_grants`.

Omitted `access_grants` continues through the frozen old `access_control` behavior, including legacy `None` and dictionaries. This deliberately leaves the measured incompatible omitted-field default unresolved: current behavior is private while this old BSD behavior treats omitted/`None` ACL as public-read. This slice does not add a default or change existing rows. Simultaneously supplied vocabularies are rejected before route execution by Pydantic form validation, but this source-only worker has not exercised HTTP status/side effects; primary owns actual API verification.

The behavior-only tool observation shows current list visibility is limited to the named reader, while a primary old-source review found that a read ACL at `/tools/id/{id}` returns a `ToolModel` containing source; current behavior withholds that source from the reader. Therefore this version deliberately rejects even the measured user/read shape rather than broaden content disclosure. The primary owns an actual Hardy check of rejected access grants and source denial.

Primary-provided corrected synthetic model observations found the same privacy broadening for `ModelForm`: current empty grants create a private model whose owner lookup returns the object and whose member/unrelated lookups return 401; old omitted ACL creates an object visible to member/unrelated. Mapping explicit empty/null to `{}` prevents object return in old ACL checks, although the old API returns HTTP 200 with null for member/unrelated rather than current 401. Model response/status parity is not claimed. Response projection/version-history parity is out of scope. No current implementation body was read. This worker has not run actual HTTP/DB validation; primary owns the pinned old-runtime check. No production security certification is implied.

`python3 backend/open_webui/test/test_explicit_access_grants.py` executes four named tests against the actual `ToolForm` and `ModelForm` class definitions extracted verbatim from the two checked-in model modules and the real shared helper, using installed Pydantic 2 without importing unavailable application dependencies. It checks legacy preservation, private null/empty mapping, actionable rejection of nonempty user/read grants, mixed-vocabulary rejection, caller-data immutability, and no persisted grant field. It does not run FastAPI, SQLAlchemy, an actual database, or an API request; primary owns the pinned old-runtime API checks. No dependency was installed.
