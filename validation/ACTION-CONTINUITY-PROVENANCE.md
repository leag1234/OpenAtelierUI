# Action caller-context continuity slice

This source change addresses the measured migrated Action gap. The current Open WebUI 0.12.4 own-data client preserved sync and async Action selection, sub-actions, caller core fields, typed `UserValves`, model, request, callback availability, chosen input, output, status, and refusal behavior. The unchanged BSD candidate preserved those facts, but successful Actions did not receive the measured profile fields or the `settings` context field.

`backend/open_webui/utils/chat.py` now constructs the existing four-field `__user__` mapping through `_action_user_context`. Only the existing `ImportedProfileUserModel` subclass, produced by the opt-in imported-profile lookup path, adds `bio`, `gender`, `date_of_birth`, and `settings`. The function calls Pydantic `model_dump(include=...)`, preserving the typed date serializer and projecting an allowlist instead of dumping the whole user. A plain `UserModel` keeps the original four-field context. The existing `UserValves` construction still runs after the projection; Action sync/async selection, request, model, callbacks, and sub-action dispatch are unchanged.

The focused source-isolated test extracts the actual Action function and the existing Pydantic user-model classes, then runs them with the installed Pydantic runtime. It checks null profile fields, JSON serialization, top-level API key/OAuth/info exclusion, fresh nested settings dictionaries per invocation, unchanged default-off context, typed `UserValves`, sync/async calls, callback and request delivery, and sub-action identity. `validation/test_imported_profile.py` also has a test-only false stub for `is_validated_api_key_request`; without it, its extracted existing session handler raised `NameError` before reaching its assertions. No auth or runtime code changed for that harness repair.

Current evidence established `settings` presence, not complete settings-value equality, so this slice does not claim full settings parity. The primary agent owns independent source review and current-versus-candidate runtime replay. No UI, event delivery, provider, authentication policy, storage schema, dependency, or default changed. The local checks do not establish full application integration or settings semantics beyond passing the existing settings object through the allowlisted field.
