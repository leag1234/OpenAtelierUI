# Atlas drop-in compatibility report correction

The maintainer supplied a 2026-11-01 integration report comparing an unchanged Atlas integration with Open WebUI v0.11.3 and the public OpenAtelierUI initialization snapshot `fe22fcb`. The private candidate had already advanced to `34a436a`; `message-input-container` and bounded Terminal/Notes implementations existed there, but the report still exposed current default and interface mismatches. This correction is independently authored from the behavior report and existing BSD project code. No later Open WebUI source was consulted or copied.

The missing-model path now distinguishes absence from authorization: an authenticated absent model returns the existing NOT_FOUND detail with HTTP 404, while an existing inaccessible model remains HTTP 401. A new authenticated profile-image route uses the same model read predicate. It serves traversal-contained files under the configured static root, decodes only bounded base64 image data, redirects client-side for existing absolute URLs, and returns explicit JSON errors for missing or invalid values. It does not fetch external URLs server-side.

The existing Terminal router is now selected automatically when `TERMINAL_SERVER_CONNECTIONS` is configured. The owner-only SQLite Notes router is available by default with an explicit `OPENATELIER_PRIVATE_NOTES_COMPAT=0` rollback switch. `/api/v1/users/all` is an alias of the existing administrator-only list operation. The SPA fallback refuses every unknown `api` or `api/*` request, preserving JSON 404 behavior instead of returning the application HTML shell.

The current UI adds stable IDs to the existing attachment, composer, stop, main-content, sidebar-name, pinned-items, and General-settings elements. These are compatibility hooks only: the underlying handlers, keyboard behavior, labels, permissions, and layout remain unchanged. Hooks that describe conditional controls remain conditional, such as stop during generation and pinned items when present.

`validation/test_atlas_dropin_report.py` exercises activation and fallback policy, missing-versus-private model status behavior, contained static image serving, administrator dependency preservation, and exactly one occurrence of every reported DOM hook. The existing Terminal, Notes, and version-metadata regressions remain required. Passing source tests do not establish the full unchanged Atlas browser journey, attachment delivery, streaming, mobile/dark rendering, complete v0.11.3 parity, migration cutover, production readiness, or human UX acceptance; those require the isolated runtime replay defined by the task contract.
