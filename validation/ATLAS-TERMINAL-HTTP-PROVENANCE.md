# Opt-in terminal attachment HTTP bridge

This candidate adds `OPENATELIER_TERMINAL_DOWNLOAD_COMPAT=1`, unset by default. Only under that flag does `main.py` import and register the `/api/v1/terminals` router, before SPA fallback. It reads `TERMINAL_SERVER_CONNECTIONS` from the existing environment and reuses the reviewed pure policy helper. No config UI, schema, dependency, auth policy, or upload behavior was added.

The authenticated list endpoint returns only enabled connections readable by the verified user. It exposes the normalized `id`, `name`, `url`, empty `contexts`, and configured `config.chat_uploads`; it omits keys, auth mode, and grants. The download endpoint accepts only GET and HEAD for the fixed generated-chat attachment path. It checks raw encoded separators and query input before policy validation, constructs a fresh upstream request with only the configured bearer, verified `X-User-Id`, and fixed `Accept-Encoding: identity`, and never forwards caller headers, cookies, authorization, query, or body. Connection read grants select the connection; the terminal remains responsible for per-file ownership.

The proxy uses the existing aiohttp dependency with `trust_env=False`, TLS verification defaults, no redirects, a 5-second connect timeout and 15-second end-to-end fetch deadline, a process-wide four-request semaphore, and a 16 MiB response cap read in 64 KiB chunks. Oversized responses return a fixed 413. Upstream 401/403/404 statuses may pass through with generic text; redirects and other unexpected statuses become fixed 502; transport failure and timeout become fixed 503/504. No exception, credential, upstream `Location`, `Set-Cookie`, or other response headers are passed to callers. Only PDF, PNG, JPEG, and plain text content types are preserved; other types become `application/octet-stream`. Responses are attachments with `nosniff`, sandbox CSP, and `no-store`. HEAD uses an upstream HEAD request and returns no body.

Unknown paths inside the enabled router resolve to authenticated 403 responses for GET/HEAD and 405 for other routed methods, rather than falling through to SPA HTML. Invalid config returns a fixed 503. Disabled, missing, or unreadable connection selections are refused before network access. The application still relies on the terminal honoring `X-User-Id`; WebUI does not prove namespace ownership itself.

## Checks and limits

`/usr/bin/python3 validation/test_terminal_http.py -v` passes 11 source-extracted route tests using a fake aiohttp session, including authorized list projection, exact attachment bytes, safe header projection, caller-header isolation, HEAD body suppression, invalid path/query/identity no-call checks, unsupported route/method status, malformed config, redirect/status/transport/timeout handling, encoded-content refusal, the exact 16 MiB boundary and overflow, and four-way concurrency. A source check confirms the exact opt-in guard and registration before SPA fallback. `/usr/bin/python3 validation/test_terminal_download_policy.py -v` passes the five pure-policy tests. `py_compile` with a temporary cache and `git diff --check` pass. No request left the process.

The first route-test attempt showed that constructing `asyncio.Semaphore` at import time fails in Python 3.9 when no event loop is installed. It was replaced with a process-level bounded semaphore acquired asynchronously. The first overflow test fixture also emitted only its short seed bytes despite advertising a larger stream; the fake stream was corrected to emit the declared synthetic remainder. No runtime route behavior was changed to hide either failure.

The route tests execute extracted function bodies with local fake sessions; they do not exercise actual FastAPI dependency wiring, the live server, DNS/TLS, a terminal, caller identity enforcement by an upstream, rate limiting, filesystem uploads, other terminal operations, orchestrator contexts, or production deployment. Primary-owned native integration and review remain required. This is not a terminal or shell feature and does not establish per-file access without an upstream that enforces the forwarded verified identity.
