# Terminal download policy prototype

This is a pure, opt-in helper; no route imports it yet. It consumes a bounded JSON connection list, creates a key-free projection for the measured direct-bearer profile, and builds an internal GET request specification only for the fixed generated-chat file path. It performs no HTTP, DNS, file access, command execution, or connection selection from caller-provided URLs.

The parser accepts at most 16 unique named entries with bounded IDs, URLs, keys, and read grants. It rejects duplicate JSON keys, non-finite JSON, unsupported authentication, malformed values, group or non-read grants, and unknown connection/config fields. User access requires an enabled connection and either a sole `user/*/read` grant or an exact `user/<id>/read` grant. Admins do not bypass this connection grant check. Empty grants deny. The helper only accepts a pre-verified server user object and constructs the `X-User-Id` header from its ID; there is no request-header parameter to forward a caller-supplied identity.

The output projection requires a verified user and filters out disabled or ungranted connections. It exposes only `id`, `name`, `url`, `contexts: {}`, and the configured `config.chat_uploads` value; it omits the bearer key, authentication mode, enabled flag, and grant principals. The observed public entry used `chat_uploads: "default"`. The parser recognizes only the measured `default` and `filesystem` modes, preserving the configured value. This read-only helper does not implement filesystem upload/write behavior. Neither mode makes a connection grant equivalent to file ownership. The generated GET carries the authenticated application identity so the terminal can enforce ownership in its own namespace; WebUI does not assert per-file ownership from connection access.

The only accepted target is one `files/serve/home/user/requests/chatcmpl-<32 lowercase hex>/<filename>` path. The filename is UTF-8 validated and encoded once without Unicode normalization. Traversal, hidden names, encoded separators/percent, alternate URLs, query/fragment, and control characters are refused. The request object hides the bearer key from `repr`, and the public projection and fixed refusal message contain no key or grant identity.

## Checks and limits

`python3 validation/test_terminal_download_policy.py -v` runs five local tests covering the key-free projection, exact owner and wildcard read grants, admin non-bypass, disabled and missing selections, malformed/duplicate config, fixed secret-free errors, Unicode filename quoting, and unsafe paths. The tests import the helper by file path so the candidate package's unrelated optional `typer` dependency is not needed. The initial package import failed with `ModuleNotFoundError: typer`; the test was corrected to load only the standalone module. The first path expectation also failed because the filename space is correctly encoded as `%20`; the assertion was corrected to the encoded target.

This prototype does not establish upstream ownership behavior, protect against a terminal that ignores `X-User-Id`, qualify other connection types, grants, file paths, upload/write operations, orchestration contexts, or any HTTP client behavior. It has not been wired into an API or native application; primary review and integration tests remain necessary. No dependencies were added.
