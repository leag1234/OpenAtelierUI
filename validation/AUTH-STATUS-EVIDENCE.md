# Missing authentication status

The only application change in this slice is the no-credential branch of the existing `get_current_user`: after the existing optional bearer and cookie fallback, absence of a token now raises 401 instead of403. Bearer/cookie selection, token decoding and expiry, API-key enablement and endpoint restrictions, user lookup, role checks, activity refresh scheduling, response details and authentication headers are unchanged.

The behavior-only 0.12.4 matrix covered three protected journeys: account self-read, private tool read and callable-model discovery. Missing credentials, invalid JWT, Basic without cookie and empty Bearer without cookie returned401. A valid owner bearer or owner cookie authenticated; valid member bearer retained member identity; member/private-tool access remained denied; filtered discovery remained available. Recognized bearer credentials took precedence over cookies even when invalid, while non-Bearer or empty-Bearer inputs fell back to a valid cookie. A valid bearer was unaffected by an invalid cookie. No token or cookie value is persisted here.

`python3 backend/open_webui/test/test_auth_missing_credentials.py` executes the actual selected `get_current_user`, `get_verified_user` and `get_admin_user` function bodies extracted from checked-in `utils/auth.py`, with local stubs for request/auth dependencies. Five named tests cover missing and empty credentials, Basic/empty-scheme cookie fallback, bearer precedence including member identity, JWT/missing-user and role refusals, and unchanged API-key enablement/path restrictions. It does not instantiate FastAPI's real `HTTPBearer`, exercise HTTP headers/cookies, JWT cryptography, database lookups, expiration, or session updates. The primary owns the pinned-runtime replay of the complete 38-request matrix. The two model-discovery alias tests and eight access-grant tests also pass. `py_compile` and `git diff --check` pass; no dependency was installed. This is not a full authentication/security certification, and unrelated status/authorization mismatches remain outside this patch.
