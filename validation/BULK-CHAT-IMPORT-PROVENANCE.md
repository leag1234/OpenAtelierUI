# Bulk chat import prototype provenance

This bounded candidate change adds the measured `{ "chats": [...] }` form to the existing chat import endpoint. The existing singleton form still calls `Chats.import_chat` with its original per-chat behavior and response. The bulk path always assigns new UUIDs and the authenticated caller as owner, sets sharing/folder/archive state to private defaults, preserves the submitted graph and integer timestamps, and commits all rows together.

The accepted profile is 1–16 chats, at most 4 MiB of serialized input and 4096 message nodes total. The prototype rejects unknown form fields, nonempty metadata, files/attachments, folders, shared or archived input, malformed timestamps and a selected message that is absent from the graph before opening the database session. Tags and other metadata effects are not imported. A second-insert failure rolls back the entire batch. Existing source IDs and submitted owner IDs are ignored; each result is a new private copy owned by the verified caller.

`python3 validation/test_bulk_chat_import.py` runs six source-extracted checks. They execute the actual preparation and model method bodies against a fresh in-memory SQLite transaction adapter, including two-item success, owner/ID/timestamp/branch assertions, a SQLite trigger that rejects the second row, pre-session refusals, bulk array routing and unchanged legacy route dispatch. The host does not have SQLAlchemy installed, so these checks do not qualify SQLAlchemy session behavior or a mounted HTTP app. The primary-owned independent real SQLAlchemy/HTTP replay remains necessary.

The first `py_compile` attempt used the host's protected default bytecode-cache path and failed with `PermissionError` before compiling sources. Re-running with `PYTHONPYCACHEPREFIX=/tmp/bulkchat-pycache` passed; no repository bytecode or source was changed by that failed attempt.

Measured current behavior is limited to the supplied synthetic current03 observations: array request and array response, private ownership, distinct copies on replay, graph/selected-answer preservation, and useful saved continuation. Folders, tags, attachments, shared imports, other metadata, broad response compatibility and production-scale resource behavior are unsupported or unqualified. This is an isolated compatibility prototype, not full API or operating-system certification.
