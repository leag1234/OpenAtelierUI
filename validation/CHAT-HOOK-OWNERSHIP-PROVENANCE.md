# Chat hook ownership slice provenance

This source73 prototype guards the existing `POST /api/chat/completed` and `POST /api/chat/actions/{action_id}` wrappers. The primary's own frozen synthetic comparison found that the current reference returned 404 without dispatch for foreign or missing saved-chat IDs, while source72 dispatched; selected own completed/async Action cases could persist fixed synthetic status into the other new private chat. These observations establish a bounded gap in the synthetic fixture, not general current-version policy or private-data exposure.

Both wrappers now call `_validate_private_chat_context` before popping `model_item`, changing request state, or invoking a handler. Absent/null IDs and the already-supported `local:` context continue unchanged. Other supplied IDs must be nonempty strings that resolve to a chat owned by the verified caller; malformed, missing, and foreign IDs receive the fixed 404 detail `Chat not found`. The check is outside the wrappers' existing broad handler-error conversion, so refusal stays 404. It uses at most one chat lookup and does not change signatures, permissions, generation, callbacks, sockets, or persistence.

The candidate's existing owner-only policy also denies an administrator's foreign-chat context, while the measured current reference allowed it. This is an explicit experimental policy divergence, not exact administrator parity or acceptance of a durable authorization policy. Shared/grant collaboration, other hook routes, and broader Action or SDK behavior remain unqualified.

`validation/test_chat_hook_ownership.py` extracts the actual helper and wrappers and supplies controlled handlers and chat storage. It verifies owner success, absent/null/local passthrough, ordinary/admin foreign refusal, missing and malformed refusal, zero handler/request-state effects on denied input, and no more than one lookup. Commands: `python3 validation/test_chat_hook_ownership.py` (2 tests), `python3 validation/test_chat_metadata_ownership.py` (6), `python3 validation/test_async_plugin_compat.py` (9), and `git diff --check`. These component checks do not replace the primary worker's independent native comparison or authorize broader security claims.
