# Bounded chat message metadata preservation

With `include_private_chat_metadata=True`, the importer now carries four validated normalized-message fields into the corresponding authoritative `chat.history.messages` node: `done`, `created_at`, `updated_at`, and `model_id`. Values are copied without type coercion; conflicting values already present in the graph refuse the candidate. The selected `history.currentId` is unchanged.

Bounds are deliberately narrow: `done` accepts booleans, integer 0/1, or exact text tokens `true`, `false`, `0`, `1`; timestamps accept nonnegative integers or ASCII decimal strings up to the year-9999 nanosecond ceiling; `model_id` accepts strings up to 256 UTF-8 bytes without control characters. Null values remain absent from the graph. Malformed values are fatal under the opt-in import. Other normalized message fields remain unsupported and reported as before. Without the existing private-chat metadata opt-in, nonempty values retain their previous unsupported-field report.

Synthetic checks set exact text-affinity source values, convert, and compare the selected branch and preserved graph values. Negative cases cover an invalid completion token, negative and oversized timestamps, and an oversized model ID; a separate assertion confirms `output` remains unsupported. Commands: `python3 -m unittest test_migrate_sqlite.ImporterTests.test_opt_in_private_chat_graph_preserves_bounded_message_fields_exactly test_migrate_sqlite.ImporterTests.test_opt_in_message_metadata_malformed_values_refuse_and_other_fields_stay_unsupported -v` and `python3 -m unittest test_migrate_sqlite -v`.

This is an own synthetic importer change only. It does not preserve the other normalized message fields, add a target table, change authorization, or establish full migration/native compatibility. Primary integration and native verification remain separate.

## Boolean-compatible normalized completion values

A primary whole-copy preview found a narrow SQLite representation mismatch: the validated `done` column can return integer `1` while the existing authoritative graph stores JSON boolean `true` (and equivalently integer `0` versus boolean `false`). Under the existing opt-in, the importer now validates both representations against the already-supported boolean forms and compares their meaning. If equal, it leaves the graph's original value and JSON type unchanged; if the graph has no `done` field, it keeps the normalized value and type. A true/false conflict or malformed graph token remains fatal. No other field comparison or conversion changed.

The local SQLite regression uses a no-affinity `done` column to retain actual integer values, verifies true/1 and false/0 equivalence while preserving graph types and the selected branch, and refuses a conflicting value and an invalid graph token. The existing test also confirms an absent graph value receives the normalized text value without coercion. Focused command: `python3 -m unittest test_migrate_sqlite.ImporterTests.test_opt_in_private_chat_graph_preserves_bounded_message_fields_exactly test_migrate_sqlite.ImporterTests.test_done_integer_equivalence_preserves_existing_graph_values_and_types test_migrate_sqlite.ImporterTests.test_done_conflict_and_invalid_graph_value_are_refused -v`. This does not broaden timestamp/model handling, rights, history, or other migration domains. Primary native whole-copy validation remains separate.

## Ordinary JSON message metadata

The copy-only importer also preserves the bounded JSON metadata written by ordinary recent chat sessions: `output`, `files`, `sources`, `embeds`, `status_history` (as graph `statusHistory`), `error`, `usage`, `context_summary` (as graph `contextSummary`) and `meta`. Existing graph values must be semantically equal; conflicts refuse the copy. Each field is limited to 1 MiB of canonical JSON and the combined metadata to 4 MiB per message. Non-finite numbers, invalid JSON, invalid required container types, excessive values and graph/preview disagreement are fatal before target publication.

This is data preservation, not execution: the importer does not run tools, follow URLs, activate credentials or manufacture grants from these values. File descriptors still pass the existing owner, join and upload checks, and copied runtime paths are remapped only by the existing validated file mapping. A synthetic 10-user, 126-chat, 46-file corpus now includes tool output, statuses, usage, attachments and prior errors; explicit partial copy preserves those fields while making unsupported shared/folder metadata private and unfoldered in the target and retaining the exact source archive. Unsupported credentials, authentication state and ambiguous rights remain inactive or refused.
