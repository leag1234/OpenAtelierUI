# Attached Text Recovery Bundle Prototype

This local-only exporter builds a deterministic `openatelier-attached-text-bundle-v1` ZIP from one selected private chat and one already-uploaded text file. It reuses the stopped-copy chat reader, strict plain-graph validator, source digest checks, and exclusive mode-0600 publisher in `export_private_text.py`. The only core extensions are optional internal graph-reader and immediately-before-link verifier hooks; existing exporter calls keep their original behavior.

The bundle contains exactly two uncompressed regular members: `manifest.json` and `attachment.txt`. The manifest embeds the existing `{ "chats": [...] }` import form, with only the three measured attachment references changed to token `attachment-1`. It also records the safe original filename, text/plain type, byte count, SHA-256, and public source-file metadata with the source file ID and user ID removed. The three original source reference entries must be equal and occur only at the measured chat, history user node, and matching selected flat-chain user message locations. The graph reader strips these exact references for validation by the existing strict text-only graph checker, then inserts the deterministic tokens. Unrecognized or multiple references refuse.

The file table must match the measured ten-column old schema and have a nonpartial unique single-column `id` index. The selected row must belong to the selected chat owner, be private, contain empty file/data maps, null file hash, the exact measured text/plain metadata profile, and a unique ID. The stored upload path is accepted only as a safe `id_filename` basename or the measured fixed old-runtime prefix `/app/backend/data/uploads/id_filename`; resolution always uses the caller-supplied copy upload root, never the stored host path. Every upload-root path component and the selected file must be non-symlink; the resolved file must be a regular file with safe matching filename, exact size, strict UTF-8, and matching optional metadata hash. The file is read only within the 256 KiB limit. The source DB is rehashed by the core publisher after staging, and the selected upload bytes/inode/stat/hash are checked again after temporary-file fsync immediately before linking the final output. A mutation or output collision refuses without replacing another file.

ZIP member order, names, timestamps, storage mode, permissions, and canonical UTF-8 manifest serialization are fixed. Preview produces only a path-free receipt; export uses the existing same-directory temporary file and exclusive link behavior. Receipts contain hashes and bounded counts/sizes, not conversation text, source paths, selected IDs, or file contents. The source DB and uploaded file are never modified. The manifest is a lab handoff format, not a directly importable current API payload; the later restorer must validate it, upload the text through the existing API, substitute that returned target DTO at only the three token locations, then use the existing bulk import route.

`python3 validation/test_export_attached_text.py` runs 12 standard-library tests for deterministic preview/export, the exact two-member ZIP and permission mode, full graph equality apart from the three token fields, measured absolute-path-prefix mapping under an explicit copy root, ownership and path refusal, file-schema/index/private-ACL/data/type/metadata/hash/UTF-8 checks, unknown/multiple/mismatched references, oversize/deadline/root-symlink refusal, late upload replacement refusal after temp fsync and temporary cleanup, diagnostic privacy, and output collisions. `python3 validation/test_export_private_text.py` still passes all 24 prior core tests. Source/test `py_compile` and `git diff --check` pass. The new exporter has 234 gross nonblank implementation lines; the existing core change adds six nonblank lines, within the respective 350- and 20-line limits.

Two local test-fixture corrections were needed: each test now rewrites its synthetic upload so a prior fixture cannot leave stale bytes, and an invalid UTF-8 case keeps its row/reference hash and size coherent so the UTF-8 refusal is actually exercised. An initial prepublication verifier reopened SQLite after the core publisher had closed its temporary-file descriptor; this could reuse the same descriptor number during failure cleanup. The final verifier relies on the core's immediately preceding whole-source digest recheck and reopens only the selected upload, checking its inode, size, timestamp, bytes, and hash before link publication. Primary review also identified the measured old runtime path prefix and header-unsafe filename characters; support is limited to that fixed prefix, and quote/semicolon and other unsafe path/header characters are rejected.

The user journey is a member exporting a branched conversation together with an attached workshop plan, then restoring it as a separate private conversation with a newly uploaded file identity. This prototype provides a deterministic local artifact and leaves original files untouched. It does not itself upload, import, or reopen the bundle, and local synthetic tests do not prove actual mounted recovery. Primary owns the stopped-copy export and fresh-target restore/reopen/continued-save run. File processing/RAG, multiple files, media, folders, sharing, broader schema variants, crash/concurrency on hostile filesystems, UI discovery/accessibility, production adoption, and general migration/cutover remain unqualified. The API/CLI checks are not human UX acceptance or macOS/Windows integration evidence.
