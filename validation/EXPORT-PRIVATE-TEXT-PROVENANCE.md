# Private Text Chat Export Prototype

This standalone BSD-3-Clause validation tool exports one selected private candidate chat as a separate current-format `{ "chats": [...] }` import artifact. It does not change the runtime, source database, schema, importer, or defaults. Preview and export are separate commands; the caller supplies both owner and chat identifiers, and the receipt never returns either identifier or conversation text.

The exporter reads a stopped, closed SQLite copy in read-only/query-only mode. It refuses symbolic-link/non-regular sources, files over 64 MiB, WAL/SHM/journal sidecars, unknown chat schemas, a changed source digest, missing or foreign-owned rows, shared/foldered/archived chats, unsupported metadata, malformed or disconnected graphs, foreign node authors, and attachment/media/tool/reference shapes. It retains the complete graph JSON, including alternate branches, the selected branch, and the matching flat chain. It emits no source chat ID or outer owner ID, creates a new private target record through the existing import contract, maps a nullable pin to false, and records nonnegative timestamps. An exact version-1 `_mdk_private_saved_work` marker may be omitted; the preview receipt states that omission. Other metadata is refused rather than dropped.

The implementation is 311 gross nonblank lines and uses only the Python standard library. It caps the source at 64 MiB, artifact at 4 MiB, graph at 4096 nodes, JSON nesting at 64 levels, and work at 10 seconds. Source hashing is streamed, applies the byte and deadline limits while reading, and confirms that the opened descriptor is the same regular file initially inspected. The digest is checked again after artifact staging and immediately before publication.

Output is a complete JSON document staged in a same-directory temporary file, created with mode 0600, then linked into a path that must not already exist. The exporter tracks the temporary inode and only removes a published path if it still names that inode. Synthetic races cover an `EEXIST` competitor, replacement after linking, and source mutation during staging; each preserves the competing/source file and removes the exporter's temporary artifact. These controls do not establish safety against a hostile filesystem or replace the stopped-copy precondition. The artifact hash and size are receipts, not proof of successful import or recovery.

`python3 validation/test_export_private_text.py` runs 20 standard-library synthetic tests covering preview/source immutability, branch and flat-chain preservation, ownership/private-row checks, metadata marker handling, optional schema fields, malformed graphs, rights/executable/media/reference refusal, sidecars/symlinks, output collision, file mode, publication failure cleanup, competing-output races, and mutation between staging and publication. `git diff --check` and `PYTHONPYCACHEPREFIX=/tmp/export-private-pycache python3 -m py_compile validation/export_private_text.py validation/test_export_private_text.py` also pass. These tests use a synthetic SQLite table, not the primary's captured candidate. No mounted current-runtime import, useful continuation, visual review, or recovery boot is claimed; primary review and its independent stopped-copy roundtrip remain necessary.

The user benefit is a portable, explicit recovery artifact for one useful conversation while keeping the original saved work untouched. Preview gives a direct eligibility answer without creating a file; export gives the user a separate artifact they can retain or import. This CLI prototype has no product UI, so discoverability, accessibility, and saved/reopened comprehension are not evaluated. It uses no background service or network. No version-specific macOS or Windows behavior is asserted; the familiar desktop convention of an explicit separate export is a usability reference, not a claim of OS integration.
