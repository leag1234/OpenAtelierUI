# Flat group membership and read-grant preparation

Recorded 2026-10-25 UTC. This is a bounded importer/read-ACL prototype for the measured flat default group profile. It is not a complete group API migration or cutover qualification.

## Behavior and source profile

The authorized 105-request 0.12.4 synthetic oracle observed one flat group, one direct member, and Tool/Model group-read grants. Adding the member changed direct resource reads from 401 to 200; removal changed them back to 401; re-adding restored 200 on the next request. Authorized member responses kept Tool content and Model parameters redacted. Group detail/member endpoints remained admin-only in this fixture. Group membership did not grant Tool or Model history access. These observations do not cover hierarchy, nonempty group permissions, write grants, wildcard principals, or general account data.

The source group profile is limited to `parent_group_id = null`, `permissions = {}`, `meta = null`, and `data = {"config":{"share":"members"}}`. Group IDs, known owners, names/descriptions, timestamps, and JSON data are copied to the old `group` row; direct `group_member` user IDs become the old embedded `user_ids` JSON list. Current membership row IDs and timestamps remain only in the byte-exact source archive and therefore block cutover. Group/read grants map to `access_control.read.group_ids` and may coexist with known targeted user/read grants. Grant IDs/timestamps remain archive-only and block cutover.

The old runtime previously searched embedded membership with `LIKE '%"<user id>"%'`, which could confuse prefixes, case variants, wildcard characters, and JSON-escaped delimiters. The bounded old-model patch retains the non-empty JSON-array SQL prefilter, then checks each ordered candidate's parsed `user_ids` list using exact string membership. Import therefore preserves valid account IDs containing `%`, `_`, quotes, backslashes, non-ASCII characters, or case variants without relying on SQL pattern matching. Malformed non-array legacy values do not grant access. Import is capped at 1000 groups and 10000 direct memberships. The runtime candidate query still scans non-empty group arrays and now performs exact checks in Python; no request-latency benchmark is claimed.

## Flat-group REST bridge prototype

The follow-up bridge implements only the measured flat-group detail, paged member read, and direct add/remove routes in the old runtime. Detail and member DTOs omit embedded `user_ids`; detail reports exact unique `member_count`. Member results expose only the observed public profile fields and suppress activity/status fields, settings, and inherited membership. The measured unique-name page is sorted by `name.casefold()` in pages of 30; tie and Unicode ordering are unqualified. Inherited membership reports zero for this flat-only profile. Group detail missing-resource response is 404 `We could not find what you're looking for :/`; member/mutation missing-resource response is 404 `Group not found.`. Missing mutation body remains a framework 422, while `{}`, null/omitted `user_ids`, and empty arrays are no-ops.

For mutation, unknown user IDs are dropped by the existing validator and rechecked inside the storage transaction. SQLite writes acquire `BEGIN IMMEDIATE` before reading, de-duplicate exact IDs, and change `updated_at` only when the direct membership list changes. A commit failure is rolled back in the isolated method test. This is a bounded SQLite implementation, not a multi-backend concurrency claim. The own synthetic current references are `safe-current-group-pagination-02.json` (SHA-256 `cf9e0a7e25f8aca8eadee2d936445741f366843aa987fde7e9fb82d388f9d98a`) and `safe-current-group-mutation-errors-01.json` (SHA-256 `a0ad1eed766ceee1cdbe3b0cb1465e583fb83f1ace458e78aec0391093390e43`); no current implementation source or complete database was used.

## Verification and limits

`validation/test_migrate_sqlite.py` checks a fresh old group table, exact group/member projection, mixed user+group read ACL, preserved source/template/archive hashes, unusual account identifiers, literal JSON `null` metadata rejection, and both resource caps. `backend/open_webui/test/test_group_membership_exact.py` executes the actual checked-in lookup method against prefix, case, `%`/`_` wildcard false positives and safe exact positives containing `%`, `_`, quote/backslash, and comma. Form projection tests cover mixed user+group read grants and reject group wildcard/write grants. Fatal no-target importer cases cover nondefault data, metadata or permissions, parent hierarchy, malformed schemas/timestamps, missing owners/users/groups, duplicate memberships, old target schema absence/mismatch, and cap exceedance.

Review correction: initial commit `549b1c8a3cabdbf1f977fd11da6bcb64dbdde7fa` changed importer behavior but omitted the required runtime exact-membership method and reusable group/read grant projection. Primary review rejected it before staging. This follow-up adds both, relaxes now-unnecessary importer ID-shape rejection, and enforces the written count caps and strict SQL-NULL metadata profile.

The importer still blocks cutover because membership/grant row identity and timestamps are archived only, alongside the existing unrelated migration blockers. This bridge does not establish complete current-client compatibility: group creation, hierarchy, full collection/list behavior, write/group grants, history access, and tie/Unicode ordering remain unqualified. Existing collection/catalog and form behavior remains the old implementation. Primary owns runtime integration and current-role replay; these local tests are not runtime qualification.
