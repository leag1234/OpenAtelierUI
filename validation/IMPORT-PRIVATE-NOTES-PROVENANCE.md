# Private notes import prototype

This opt-in, standard-library-only converter maps a measured private notes subset from a closed SQLite source bundle into a separate copy of an already migrated target database. It is not a complete profile migration, uploads copier, deployment action, or durable adoption decision.

The tool copies and hashes the source database and any present WAL/SHM files into private scratch before SQLite reads. It refuses rollback journals and target sidecars. It opens the target only through a private copy, requires the measured target table shape and an empty prefixed notes table, and verifies matching owner identity and role in both databases. A same-owner `user` or `admin` profile is supported; pending/unknown roles, notes grants, malformed data, unsupported pins, collisions, and changed inputs refuse before publication. The target is published with an exclusive hard link; a competing output is never removed.

For every accepted note, the tool preserves its ID, owner, title, dates, JSON text or SQL NULL, and the same-owner pin relation. It does not copy uploads, rewrite paths, import other grants, modify an input, or enable any runtime feature. Reports contain counts and file hashes, not note contents or identities. Cutover is always false. The report also records whether this small-fixture run met the provisional two-second target; the separate 30-second bound is a safety timeout, not a performance claim.

The local tests use real temporary SQLite databases, including opaque JSON `null` versus SQL NULL, an unrelated grant and target row, matching admin-owned notes, refusal cases, a source-change race and an output-creation race. The current baseline also showed an unowned administrator can read a note in the reference while the existing own API denies that request; this tool does not change that access policy or claim that difference is resolved. Tests do not establish behavior on hostile filesystems, live writers, crashes or power loss, PostgreSQL, uploads, full-profile migration, application startup, or rendered UI. Primary-owned integration and unchanged-client checks are required before any broader compatibility claim.
