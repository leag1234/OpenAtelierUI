# Lazy local embedding startup experiment

This default-off experiment starts from candidate source52 (`0a69cbf1f592293447a1a5879fcdb83461f51b2c`). Its own measured contract found that startup calls the existing `get_ef` factory eagerly, and a configured nonempty local model imports SentenceTransformer inside that factory. The candidate process measured 709.08/709.65 MiB PSS before and after mapping. The aggregate observation does not identify the anonymous memory by module, so this change tests a startup hypothesis and does not claim a memory or energy gain.

When `OPENATELIER_LAZY_LOCAL_EMBEDDING_STARTUP=1`, and only when startup has the existing empty-string local engine and a nonempty embedding model, `main.py` places `DeferredLocalEmbedding` in `app.state.ef`. The wrapper captures the existing `get_ef` callable, engine, model and auto-update setting. It calls that factory on the first `encode`, under a built-in lock, and forwards the original encode arguments and result. The default flag-off path, nonlocal engines, empty model, reranker initialization, embedding factory/function and config-update route remain on their existing eager paths.

Initialization is attempted once. A factory exception is retained and re-raised on later encode calls; a `None` factory result is retained and produces a visible `RuntimeError` on every encode. There is no background task, extra executor, automatic retry or model download policy change. First encode can have a cold delay. Warm calls forward directly and are not serialized by the initialization lock. Object identity/type inspection and arbitrary direct mutation of `app.state.ef` are outside this prototype.

The source-isolated suite is `python3 validation/test_lazy_local_embedding_startup.py` (7 tests). It executes the actual startup `try` block extracted from `main.py` with controlled factories and checks strict default-off selection, local/nonlocal/empty-model selection, captured arguments, unchanged encode forwarding, single-flight concurrent initialization, warm reuse, and visible cached `None`/exception outcomes. The existing Filter SDK suite (`python3 validation/test_filter_sdk_compat.py`, 8 tests) and priority suite (`python3 validation/test_filter_priority.py`, 7 tests) also pass. The actual installed SentenceTransformer check with a tiny locally generated random-weight model, app integration, first-use latency, memory profile and unchanged SDK journey are primary-owned and have not been run by this worker.

The first test invocation found a test-only AST extractor that missed assignments nested in an `if`; the extractor was corrected and the seven-test suite passed. An initial grouped check used the monorepo working directory with candidate-relative test paths and failed to locate those files; rerunning from the candidate passed. The initial `py_compile` invocation failed because Python tried to write bytecode into a protected user cache directory. Re-running with an explicit temporary `PYTHONPYCACHEPREFIX` succeeded. The repository checker and dashboard check passed. No runtime, model download, external service, provider, data, or host operation was performed by this slice.

This is an opt-in component spike, not a durable default, whole-image performance result, model-quality claim, complete RAG qualification, or architecture decision. The previously measured startup PSS target remains unmet by evidence because no post-change process profile was run here.
