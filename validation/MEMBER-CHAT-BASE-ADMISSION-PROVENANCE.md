# Plugin-backed model preset base admission

Recorded 2026-10-25 for the pinned old BSD candidate. The bounded current behavior summary is from `evidence/TASK-OPENATELIER-MEMBER-CHAT-001/worker-handoff.md`: current0.12.4 requires read access to both the selected preset and its separate base plugin Model row; source25 had 12 unauthorized successes in the 74-call comparison. The own safe HTTP/SSE evidence named there is `safe-current-base-admission-01.json` (SHA-256 `678d2bbb4a63d2367f857daf35156b8a04f0602a9df7405fa9a37facae067d46`). No current implementation source, full auth/config/session data, provider, or plugin source was read or changed.

The old candidate already checked the selected `Model` row in the chat route, then dispatched Pipe entries through `generate_function_chat_completion`. This patch adds a second per-request check at the start of that function, before tool construction, user-valve reads, module loading, or pipe invocation. It applies only to role `user`, a selected model entry with a `pipe` marker, and a persisted selected Model row with nonempty `base_model_id`; it asks the existing `check_model_access` policy to authorize that base Model ID. That existing policy handles owner, public read, named user/group read, and denial. The existing global access-control bypass and admin paths skip the added check. Bare Pipe rows without a base rewrite retain their old behavior. The check re-reads the base Model on every call, so it does not rely on cached catalog authorization.

The patch leaves model discovery, refresh behavior, provider rules, active-state cache invalidation, and plugin loading unchanged. It does not prevent discovery-time trusted plugin module imports. This preserves the existing user journey after the administrator has explicitly granted access to both the preset and its base plugin; the extra base permission is an additional setup step that should remain visible to administrators. No UI, provider, broad plugin-security, arbitrary deployment, or durable permission-model claim is made.

Review correction: commit `20f9241955b80b4b265986565cf97f25ad452fdb` imported `BYPASS_MODEL_ACCESS_CONTROL` from `open_webui.config`, which does not export it in this old runtime. The primary's immutable stage26 replay exposed an import error on all guarded preset calls (8 of 16 positive member replies lost); the commit is retained unchanged. This follow-up imports the existing symbol from `open_webui.env`, where `env.py` defines it and `main.py` imports it for the selected-model gate. The source-bound test reads the real assignment expression and verifies the dispatch import path, so the test no longer invents an export in `config.py`.

It covers denied plain and streaming requests before tools, successful base owner/user/public/group read paths, missing/revoked base denial on the next call, admin/global bypass, and a bare plugin without a base rewrite. These are source-isolated tests; primary owns the fresh source27 replay, exact plain/SSE data comparison, and source preservation checks.
