# Explicit async model compatibility spike provenance

This is a default-off adapter for a later fresh-volume evaluation. It changes no HTTP route, database model, configuration default, auth behavior, or dependency. It does not establish Atlas compatibility or product readiness.

`run_verified_bootstrap(script_path, expected_sha256, args=())` is the explicit launcher entry point in `open_webui.utils.async_model_bootstrap`; it is also available as `python -m open_webui.utils.async_model_bootstrap SCRIPT SHA256 [ARGS...]`. The helper accepts only a regular non-symlink file whose bytes fit within 1 MiB and match the supplied SHA-256. Nonblocking open prevents a FIFO from hanging before file-type refusal. The exact bytes read and hashed are sent over stdin to a new child process; later path changes cannot replace those bytes. Arguments are separate argv strings, no shell is used, and stdout/stderr are discarded. The child imports the existing application config before executing the selected script, temporarily proxies only the six named Functions/Models calls with `asyncio.to_thread`, and restores the original module bindings on normal return or exception. Nonzero child status is returned without script output or exception text; `SystemExit()` maps to success. This is an explicit script execution feature, not a sandbox; the operator-selected script runs with the child process's ordinary application privileges.

`adapt_filter_module` extends the existing task-local Filter SDK bridge. Only module-level direct/aliased `Files` or `Chats` bindings and exact module-level `importlib` / `import_module` bindings are adapted. Selected exact imports of `open_webui.models.files` and `open_webui.models.chats` receive a local module view for `Files.get_file_by_id` or `Chats.get_chat_by_id_and_user_id`. No `__builtins__`, `__import__`, or package view is intercepted, and non-target imports keep their original identity. Local imports inside an already-created handler are outside this slice. Async handlers receive worker-thread awaitables; sync handlers and constructors retain native synchronous values. The wrappers preserve positional/keyword arguments, return values, `None`, and exceptions, including the existing caller-supplied chat owner ID. Repeated adaptation is idempotent. The adapter does not replace process-wide model attributes or `sys.modules`. The existing direct Users bridge and `utils/filter.py` task-local mode/reset remain, including reset after error or cancellation.

Focused validation: `validation/test_model_async_compat.py` passes eight tests covering the selected plugin/model methods, off-loop calls and a heartbeat, `None`/error propagation, direct and aliased bindings, exact dynamic imports, non-target import identity, unchanged builtins, repeated adaptation, synchronous mode, script path/hash/size/FIFO refusal, verified-byte use after a path change, CLI argument/status mapping, child config-import ordering, and singleton restoration. Existing `validation/test_filter_sdk_compat.py` passes eight tests, `validation/test_filter_priority.py` passes seven, and `validation/test_plugin_load_preservation.py` passes four. `py_compile` succeeds with `PYTHONPYCACHEPREFIX=/tmp/openatelier-atlas-compat-pycache`; an initial compile without that environment setting was denied while trying to write into the read-only user cache. `git diff --check` passes.

The initial committed draft used a module-local builtins importer and package views. Review correctly identified that this exceeded the observed module-binding requirement and could alter import identity. The correction removes that interception and uses `sys.modules` singleton identity only; target models are not eagerly imported. The first test pass also exposed two harness issues: the Users fixture lacked its already-loaded module, and the loader detector treated a `None` global as the missing importlib module. Both were corrected; the focused regression suites now pass. Earlier first-draft loader tests had also caught eager Files/Chats imports; the retained loader only activates for exact already-loaded module/singleton or importlib bindings.

No external bootstrap was executed. Tests use synthetic modules and a mocked process boundary; they do not establish actual application database behavior, installed-plugin compatibility, Python deployment compatibility, task cancellation semantics of every native SDK caller, or an isolation/security boundary for selected code. Unsupported import patterns include wildcard interception, copied/re-exported APIs outside the selected module bindings, dynamic aliases other than the exact observed module paths, and non-listed model methods. Existing asynchronous Filter dispatcher behavior is reused; broader plugin types and arbitrary imports remain unqualified.
