# Async model compatibility provenance

This adapter changes no HTTP route, database model, authentication behavior, dependency, or process-wide SDK singleton. It provides a bounded compatibility path for Filter plugins that directly await two model lookups exposed synchronously by the BSD runtime.

`run_verified_bootstrap(script_path, expected_sha256, args=())` is the explicit launcher entry point in `open_webui.utils.async_model_bootstrap`; it is also available as `python -m open_webui.utils.async_model_bootstrap SCRIPT SHA256 [ARGS...]`. The helper accepts only a regular non-symlink file whose bytes fit within 1 MiB and match the supplied SHA-256. Nonblocking open prevents a FIFO from hanging before file-type refusal. The exact bytes read and hashed are sent over stdin to a new child process; later path changes cannot replace those bytes. Arguments are separate argv strings, no shell is used, and stdout/stderr are discarded. The child imports the existing application config before executing the selected script, temporarily proxies only the six named Functions/Models calls with `asyncio.to_thread`, and restores the original module bindings on normal return or exception. Nonzero child status is returned without script output or exception text; `SystemExit()` maps to success. This is an explicit script execution feature, not a sandbox; the operator-selected script runs with the child process's ordinary application privileges.

`adapt_filter_module` extends the existing task-local Filter SDK bridge. The historical direct Users bridge is unchanged. At load time, `source_awaits_filter_model_lookup` parses the same source that the loader compiles. It enables Files/Chats adaptation only when every occurrence of either supported method is a direct awaited call: `Files.get_file_by_id` or `Chats.get_chat_by_id_and_user_id`. A plugin with an unawaited occurrence, a mixed awaited/unawaited use, or another method keeps native synchronous behavior. The existing exact authoritative-function override `OPENATELIER_ASYNC_FILTER_MODEL_IDS` remains available for separately qualified exceptional code; it is no longer required for consistently awaited plugins. Only module-level direct/aliased `Files` or `Chats` bindings and exact module-level `importlib` / `import_module` bindings are adapted. Exact imports of `open_webui.models.files` and `open_webui.models.chats` receive a local module view. The override is bounded to 4096 UTF-8 bytes and 32 unique IDs; each ID must be 1–128 ASCII letters, digits, underscore, dot, or hyphen. Invalid JSON, duplicate IDs/keys, wrong types, wildcard or malformed IDs produce a fixed configuration error without echoing the input. No `__builtins__`, `__import__`, or package view is intercepted, and non-target imports keep their original identity. Async handlers selected by the existing dispatcher receive worker-thread awaitables; sync handlers and constructors retain native synchronous values. The wrappers preserve positional/keyword arguments, return values, `None`, and exceptions, including the existing caller-supplied chat owner ID. Repeated adaptation is idempotent. The adapter does not replace process-wide model attributes or `sys.modules`. The existing `utils/filter.py` task-local mode/reset remains, including reset after error or cancellation.

Focused validation after automatic detection: `validation/test_model_async_compat.py` covers bootstrap behavior, all selected plugin/model methods, off-loop calls and heartbeat, `None`/error propagation, direct/aliased bindings, the attachment-filter dynamic-import shape, non-target import identity, unchanged builtins, repeated adaptation, automatic awaited lookup without product-specific configuration, unawaited and mixed-use preservation, the exact-ID override, invalid and oversized allowlists, safe refusal text and no function deactivation, script path/hash/size/FIFO refusal, verified-byte use after path changes, CLI argument/status mapping, child config-import ordering, and singleton restoration. Existing `validation/test_filter_sdk_compat.py`, `validation/test_filter_priority.py`, and `validation/test_plugin_load_preservation.py` remain required regressions. `py_compile` uses a task-owned cache; `git diff --check` is required.

The initial committed draft automatically bridged Files/Chats for every async Filter, which could change legacy handlers relying on synchronous results. The exact-ID allowlist restored the legacy default. The later production follow-up demonstrated that requiring a product-specific environment value was not drop-in compatible. Source-level awaited-call detection now selects the already-bounded bridge while refusing to reinterpret mixed call styles. The earlier broad builtins import hook remains absent; module discovery uses already-loaded singleton/module identity without eager model imports.

No external bootstrap is implied by these tests. Tests use synthetic modules and a mocked process boundary; exact-image runtime, stored-chat continuation and browser checks remain separate release gates. Unsupported import patterns include wildcard interception, copied/re-exported APIs outside the selected module bindings, dynamic aliases other than the exact observed module paths, indirect awaiting, mixed awaited/unawaited use without the explicit override, and non-listed model methods. Existing asynchronous Filter dispatcher behavior is reused; broader plugin types and arbitrary imports remain unqualified.
