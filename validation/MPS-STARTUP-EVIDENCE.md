# Platform-gated MPS availability probe

The old environment module probed MPS unconditionally after CUDA selection, importing `torch` on Linux even when CPU was selected. The bounded change runs the availability check only when `sys.platform == "darwin"`. CUDA selection, CUDA failure fallback and MPS exception fallback remain in the existing branches. This is a platform-specific startup hypothesis; it does not change engine, model or device defaults.

To preserve the old public `torch` binding without eager Linux import, the environment module now loads and caches the real module through a small stdlib `importlib` helper when CUDA/MPS checks need it or when a consumer explicitly accesses/imports `open_webui.env.torch`. PEP 562 module `__getattr__` resolves explicit imports; `__all__` continues to list existing public globals and includes `torch` when already imported or discoverable as installed, so wildcard imports resolve the real module when available and do not fail solely because torch is absent. Module `__dir__` also advertises lazy public exports without importing torch, preserving discovery by introspection. No proxy or `sys.modules` replacement is used. First explicit `torch` access still pays the real import cost.

`python3 backend/open_webui/test/test_env_torch_import.py` runs four named tests against the actual checked-in CUDA/MPS branches and lazy export definitions with injected importer/platform objects. It checks Linux/Windows no-eager-import CPU paths, macOS MPS available/unavailable/error outcomes, CUDA available/unavailable/import-error fallback, actual-object identity through explicit attribute resolution, installed/absent wildcard export lists, and cached module reuse. The first test harness draft accidentally executed the stdlib `import importlib` node in the extracted block, replacing its fake importer and attempting the host torch import; that attempt failed because the installed NumPy binary was x86_64 while the host Python process was arm64. The selector was corrected to execute only the relevant env branches/helper definitions, and the current tests do not import host torch. `PYTHONPYCACHEPREFIX=/tmp/openatelier-mps-pycache python3 -m py_compile backend/open_webui/env.py backend/open_webui/test/test_env_torch_import.py` and `git diff --check` pass. No dependencies or accelerator were installed or used.

The primary's old-source import trace recorded torch cumulative import time of 2.500 seconds within `env.py`'s 3.411-second path, followed by a separate configured `sentence_transformers` import of 4.824 seconds. These are trace timings, not memory attribution or measured savings. The configured local-embedding profile may still import torch later, so the default-profile gain is unknown and may be zero. The primary owns paired runtime A/B checks for the same existing configured profile and a separately identified synthetic no-local-embedding profile, with the same inputs and hardware. No real Linux process, Windows, macOS, CUDA, MPS device, RSS/PSS or latency qualification is claimed here; no product default or whole-embedding/vector lazy-load decision is made.
