# Named OpenAPI server compatibility slice

This independently authored BSD-3-Clause slice addresses the measured named-server catalog and dispatch mismatch in the bounded `TASK-OPENATELIER-OPENAPI-TOOLS-001` handoff. The current black-box result supplied for this work showed only administrators receiving `server:synthetic_openapi`; ordinary members and unrelated users did not receive the row, and anonymous access returned 401. It did not establish general grant semantics. The prior old response-wrapper correction remains in its separate commit.

For explicit `type=openapi`, `spec_type=url` rows with a valid `info.id`, the old catalog now emits `server:<id>` only when the configuration is enabled, the ID is unique, and exactly one cached server entry matches the current in-memory binding. The original list index remains the connection lookup index. Named catalog entries are visible only to administrators, and named selection is checked again in `get_tools` before any callable is made. Numeric aliases for named rows, malformed, duplicate, disabled, and stale mappings fail closed. A local plugin row that collides with a reserved named ID causes that selection to be rejected before callable construction. The server binding stored in the in-memory cache is a digest; URL text, credentials, headers, and config are not added to the public response.

Legacy unnamed numeric server IDs retain their existing dispatch path. Ordinary local plugin IDs outside a named-server namespace retain their prior lookup path. Named grant forms, member sharing, dedicated specs and direct-server routes, exact metadata values beyond the measured ID/visibility result, simultaneous configuration refreshes, and invocation behavior during in-flight cache replacement are not qualified here. The catalog retains old response fields; it does not claim current response-shape parity. A matching local ID is deliberately ambiguous and unavailable through this prototype.

`python3 validation/test_named_openapi_server.py` source-extracts the actual old helper and `get_tools` functions, injecting only database/cache and server-execution stubs. It exercises canonical admin dispatch, member denial, numeric-alias denial, local-ID ambiguity, disabled/stale/duplicate/malformed failures, sparse original connection indices, and the legacy numeric path. These are source-bound unit checks, not a mounted application or live server test. The primary agent owns the isolated runtime replay and review. The earlier `validation/test_tool_server_verify_response.py` remains a separate regression check.

The first test run exposed two test-harness defects (the extracted namespace omitted the ID regex constant, and a local-tool stub used a mapping where the source reads a `.specs` attribute); both were corrected, after which all five named-server tests passed. A normal `py_compile` attempt could not create its cache under the host's restricted Python cache path; compiling both edited modules in memory succeeded. These host checks do not replace the primary mounted-runtime test.
