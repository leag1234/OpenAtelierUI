# Named OpenAPI server compatibility slice

This independently authored BSD-3-Clause slice addresses the measured named-server catalog and dispatch mismatch in the bounded `TASK-OPENATELIER-OPENAPI-TOOLS-001` handoff. The current black-box baseline without a grant showed only administrators receiving `server:synthetic_openapi`; the positive trial with one configured user/read grant showed the named server to that member and the administrator, but not an unrelated user. Anonymous access returned 401. This establishes only that exact grant case. The prior old response-wrapper correction remains in its separate commit.

For explicit `type=openapi`, `spec_type=url` rows with a valid `info.id`, the old catalog now emits `server:<id>` only when the configuration is enabled, the ID is unique, and exactly one cached server entry matches the current in-memory binding. The original list index remains the connection lookup index. Without an explicit grant, named catalog entries are visible only to administrators. The one measured ordinary-user case is supported by a fresh exact match to a single `user`/`read` entry in `config.access_grants`; that check is shared by catalog filtering and callable resolution and is not cached. Numeric aliases for named rows, malformed, duplicate, disabled, and stale mappings fail closed. A local plugin row that collides with a reserved named ID causes that selection to be rejected before callable construction. The server binding stored in the in-memory cache is a digest; URL text, credentials, headers, and config are not added to the public response.

Legacy unnamed numeric server IDs retain their existing dispatch path. Ordinary local plugin IDs outside a named-server namespace retain their prior lookup path. The named-only response projection emits the measured nine keys, `version_id: null`, and `access_grants: []`; it does not expose the configured connection grant. Other metadata values, dedicated specs and direct-server routes, simultaneous configuration refreshes, and invocation behavior during in-flight cache replacement are not qualified here. A matching local ID is deliberately ambiguous and unavailable through this prototype.

`python3 validation/test_named_openapi_server.py` source-extracts the actual old utility and catalog route functions, injecting only database/cache, Pydantic-response, and server-execution stubs. It exercises canonical admin dispatch, matching member selection, unrelated/reassigned/removed-grant denial, unsupported grants, named-only metadata projection with a colliding local ID, numeric-alias denial, disabled/stale/duplicate/malformed failures, sparse original connection indices, ordinary-local no-config-read, and the legacy numeric path. These are source-bound unit checks, not a mounted application or live server test. The primary agent owns the isolated runtime replay and review. The earlier `validation/test_tool_server_verify_response.py` remains a separate regression check.

The first test run exposed two test-harness defects (the extracted namespace omitted the ID regex constant, and a local-tool stub used a mapping where the source reads a `.specs` attribute); both were corrected, after which all five named-server tests passed. A normal `py_compile` attempt could not create its cache under the host's restricted Python cache path; compiling both edited modules in memory succeeded. These host checks do not replace the primary mounted-runtime test.


The source40 unchanged sharing comparison found the ordinary member absent from the candidate baseline; the measured positive current comparison showed the member row. The candidate baseline had no `version_id` and projected a one-entry legacy-derived grant list, while current returned `version_id: null` and an empty `access_grants` list. The named-only projection addresses those observed key/value differences without transforming local or unnamed rows. The current mounted replay of this implementation has not yet run; no current parity, tool invocation, or security-completion claim is made.

Primary review then found that long zero-padded numeric aliases were not recognized by the reservation check and that local selections read `TOOL_SERVER_CONNECTIONS` unconditionally. The follow-up keeps numeric alias detection string-based (without integer conversion), caps numeric parsing in the legacy resolver, and reads server config only for `server:` selections. Added source-extracted tests cover a 5,001-digit alias against a colliding local row, an oversized numeric resolver input, and a local selection whose server-config property raises if read. Same-string local and legacy objects retain their prior response path. The named suite now contains nine test cases; primary mounted replay is still required.

Primary source review found that a matching grant alone could authorize a non-user role or an empty caller ID in the extracted helper contract. The follow-up preserves the admin path, requires ordinary role `user`, and rejects empty/whitespace caller and principal IDs. Targeted extracted tests cover pending/unknown roles and empty or whitespace identities. This correction is not based on a mounted-API exploit finding; the verified-user guard was separately expected to constrain callers.

## Named tool continuation response headers

The current04 bounded fixture returned three exact useful replies through the unchanged plugin/client. On the unchanged source41 candidate, the same19-call scope and closure controls passed, but all three positive replies were result-unavailable; five strict comparison assertions failed on the positive response contract/equality. These observations and retained receipts are primary-owned. They establish only the measured named-server continuation case, not general plugin parity.

The old transport now has an optional keyword-only `include_response_headers=False` on `execute_tool_server` and `get_tools`. The trusted `functions.__tools__` injection site opts in. `get_tools` forwards that option only after the existing named binding, freshness, collision, and exact read-grant gates have succeeded. An opted-in successful request returns the decoded payload together with the exact `response.headers` object. Default calls, internal callers, legacy unnamed servers, local plugins, and error dictionaries retain their prior result shapes. No request field controls the option.

`python3 validation/test_named_openapi_server.py` runs15 actual source-extracted tests, including default and opted-in named paths, permission rejection, legacy and local no-forwarding, and the trusted call site. It also executes the actual extracted transport function against a controlled asynchronous response to check payload/header object identity and HTTP/JSON failures. `python3 validation/test_tool_server_verify_response.py` runs5 source-extracted regressions. These tests do not perform a mounted app request or network call; the primary agent owns the unchanged19-call runtime replay and header-sensitive continuation comparison. Header values are neither recorded nor asserted here. The broader response-header contract, SSE/error parity, native model-generated tool loops, and other tool servers remain unqualified.

## Bounded catalog schema freshness correction

The current synthetic own-server comparison found that an enabled named no-auth server could change its OpenAPI route while the old process kept serving the cached schema: the unchanged pipe still called the removed operation twice and returned result-unavailable, while current fetched the changed catalog and completed the unchanged pipe. The follow-up refreshes catalog entries on the existing tool-catalog request only. It fetches only unique, valid, enabled explicit named URL connections with `auth_type: none`, an empty key, no configured headers beyond absent/null/empty, and no cookie forwarding. Fetches are made through the existing schema loader with the original connection index restored in cache entries. A failed refresh removes that named entry from the cache instead of falling back to its stale schema. Legacy numeric server entries keep their prior cached object and order. If no connection qualifies, the old cache object is returned unchanged.

Malformed/duplicate IDs, disabled entries, credentialed connections, URL userinfo, configured header forwarding, and cookie forwarding do not trigger this refresh. Existing binding, grant, alias and collision checks remain in place. Initial empty-cache bootstrap still uses the existing loader path; this slice does not change it. Only ordinary catalog requests are covered. Invocation-time freshness without a catalog request, simultaneous configuration mutation during refresh, concurrency behavior, real HTTP fetch behavior, and mounted app parity remain with primary-owned validation. No new network destination, route, request toggle, credential/header forwarding, dependency, cache TTL, or persistent setting was added.

The named suite now runs18 source-extracted tests with `python3 validation/test_named_openapi_server.py`. New tests show changed schema replacing the cache at the original sparse index, a failed refresh removing only the stale named entry while retaining legacy data, and unchanged no-fetch behavior for local-only or ineligible named shapes including malformed, duplicate, disabled, credentialed, header-forwarding, and cookie-forwarding cases. The first run of the extracted route tests exposed that the isolated test namespace omitted the newly used standard-library URL parser; the namespace was corrected and the full suite rerun. This is source-bound test evidence only; the primary owns the unchanged current/candidate runtime comparison.

### Refresh index-validation correction after commit 06ea8c2

Primary review found that malformed cached `idx` values could be compared to eligible integer indices before the existing catalog route's integer guard, and Python considers boolean `False` equal to integer zero. The follow-up preserves cached entries with non-integer or boolean indices, excludes them from named catalog-index matching, and lets the existing route skip them. Fetched entries are accepted only when `idx` has exact integer type and equals zero. Tests cover cached list, dictionary, null, string, and boolean indices alongside a valid legacy entry and successful refresh; a loader response with `idx: false` is refused and its stale named entry is removed. The named suite now runs20 source-extracted tests; `python3 validation/test_tool_server_verify_response.py` remains5 passing regressions. The earlier commit is preserved, and mounted runtime replay remains primary-owned.
