# OpenAI-compatible endpoint configuration import prototype

This importer-only default-off slice preserves four measured configuration rows in a fresh candidate copy: endpoint enablement, one base URL, one API key, and an empty per-endpoint options object. The selected source values map to the old target's `openai.enable`, `openai.api_base_urls`, `openai.api_keys`, and `openai.api_configs` settings, merged into the existing verified pinned-default configuration record. The public option is `--include-openai-configuration` and the Python keyword is `include_openai_configuration`.

The source contract was measured against an own Open WebUI 0.12.4 loopback fixture. It used exactly one HTTP loopback `/v1` endpoint, one fake credential, and empty options. The corresponding source60 import baseline omitted these settings and left configured model discovery and four selected plain/SSE completions unavailable. The source facts and unchanged client comparison are in the task's safe `current-contract-01.json` and `baseline-gap-01.json`; no current implementation or credential is included here.

The importer refuses duplicate, missing, malformed, oversized, aliased, parent, overlapping, or descendant settings before target creation. It accepts only a JSON boolean, a single validated bounded HTTP(S) endpoint without credentials/query/fragment/control/whitespace, a single nonempty bounded ASCII key without whitespace/control characters, and an exactly empty options object. It preserves accepted endpoint/key values byte-for-value as decoded JSON values, never includes the key in diagnostics, and allows unrelated `openai.*` siblings to remain archive-only blockers. Selected settings always retain an explicit prototype blocker and do not enable cutover. Existing config selectors compose into one target config record; old defaults remain pinned and unchanged.

Local verification passed seven focused OpenAI import tests, seven API-key configuration tests, eight user-permissions tests, and 51 general importer tests. The suite exercises preview/convert through the CLI, exact target mapping, false enablement, selector composition, strict hostile shapes, secret-redacted diagnostics, and unrelated sibling retention. The first test run exposed three test-expectation issues: the secret-redaction negative used a valid key, the expected nested config shape was incorrectly keyed, and JSON `true` is correctly accepted. Those fixtures/assertions were corrected; the rerun passed. A bytecode compile initially attempted a cache path outside the writable workspace; rerunning with `PYTHONPYCACHEPREFIX` set to `/tmp/openatelier-provider-pycache` passed. `git diff --check` passed.

This is static import validation only. It does not contact or validate any endpoint, prove authentication/provider compatibility, qualify multiple endpoints or keys, support custom headers/advanced options, enable a provider, change runtime code/defaults/schema/dependencies, or resolve remaining configuration blockers. Primary review and the unchanged isolated current-client replay remain required.
