# Optional native foreground launcher

This opt-in prototype prepares a private copy and starts one foreground Uvicorn process on loopback. It does not change the Docker lifecycle, install packages, create a service, or claim CPU/memory/network isolation. Ctrl-C is the direct stop control; the private workspace and pre-session database remain for recovery and comparison. Reopening an already-prepared workspace is not implemented by this prototype.

The launcher reuses the existing closed-tree validator, profile-schema classifier, session-epoch copy tool, and qualified environment flags from `openatelierui_instance.py`. It checks the source before and after copying, retains a pre-session database, merges the candidate static tree with the exact supplied frontend static tree, and records source, upload, pre-session, and prepared-database hashes. Only `WEBUI_SECRET_KEY` is accepted from the mode-0600 operator env file; the value is never included in the report.

Local tests mock the Python version response and final Uvicorn process. They execute the existing standard-library SQLite copy helper against a synthetic database but do not import or start the application, bind a listening port, or test a real venv. One initial test exposed that this host's Python did not satisfy the launcher’s required 3.11/3.12 range; the focused command was corrected to mock that version check rather than weakening the requirement.

Invoke the opt-in tool from the candidate checkout with `python3 -m validation.openatelierui_native --help`. The launcher keeps the selected `venv/bin/python` path rather than resolving its symlink, so Uvicorn runs with that environment's installed packages; a focused regression checks absolute and caller-relative venv paths.

Review correction: the first implementation resolved the venv interpreter symlink and would have launched the base Python, losing the virtual environment's site-packages. `_python` now normalizes the invocation path without resolving its final symlink. The regression uses a temporary `venv/bin/python` symlink and verifies the generated Uvicorn argv retains it. The designated test bytecode cache was inspected: owned by UID 501, no symlinks, and only `.pyc` files (2,720 KiB allocated); it was removed after the tests. Filesystem free space then measured 115,479,564 KiB.

A primary-run Linux process qualification used implementation `b0d73851be76ec6583f5c09de0d20a2aae82bd49` with the frozen core10 backend and compiled frontend. The existing image supplied offline dependencies and network/process isolation; the launcher itself invoked no Docker command. A fresh Python3.11 system-site-packages venv started the real ASGI application. Health, version and frontend HTTP succeeded, the imported synthetic account signed in, and one saved history entry returned. Readiness was17.61seconds in that single run, not a comparative speedup. Original database/uploads remained identical and the copied target passed SQLite integrity after shutdown.

The probe deliberately sent SIGTERM to its exact Uvicorn child. Installed Uvicorn0.34 re-raises that signal after awaited shutdown; the native wrapper therefore exited241 on Unix, while the successful test controller exited0. The child and listening port were closed. Ctrl-C behavior still needs its own qualification. Initial path/schema refusals and an incorrect test expectation of launcher exit0 are retained in the parent evidence, rather than rewritten as successful runs.

Supply a canonical plain compiled-frontend directory: the image's `/app/build` is a symlink and is intentionally refused; resolve it to its actual plain directory before calling the launcher. The supported source in this test was a preserved importer output before session preparation. Already-prepared session schemas refuse; do not remove session columns to bypass that refusal. Resume support is still absent.

The checkout itself has no compiled `build/` directory. Direct host installation, complete native dependency provisioning, saved-work reopen, actual UI rendering through this launch path, resource/performance comparison and complete failure cleanup remain unqualified. This is a foreground-launch prototype, not a general usable-native release.
