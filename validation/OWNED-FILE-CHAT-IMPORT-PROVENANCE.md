# Owned Text File in Bulk Chat Import Prototype

This bounded prototype extends only `backend/open_webui/models/chats.py`. It accepts the measured existing uploaded-file shape in the bulk chat import path while leaving singleton imports, no-file bulk imports, the router, file DAO/model, schema, frontend, exporter, and dependencies unchanged. The implementation adds 125 gross nonblank runtime lines against `33fe23c6`, below the 180-line allowance.

The accepted request contains one distinct file ID at most across the batch. Within an individual chat it must occur in exactly three measured locations: `chat.files[0]`, the matching user-role history node's `files[0]`, and that same user's selected flat-chain message `files[0]`. The history reference must lie on the selected ancestry, and the flat message IDs must match that ancestry in order. The three reference objects must agree. The item and embedded public file DTO have exact allowlisted keys. It is a declared `text/plain` profile, at most 256 KiB, with empty `data` objects, a nullable `hash`, empty processing error, uploaded status, matching relative file URL, and the measured metadata fields. Other nonempty attachment, media, collection, tool, rights, sharing, or unknown reference shapes refuse.

After all chat forms are structurally prevalidated, the importer resolves the one distinct ID through the existing `Files.get_file_by_id` lookup at most once. It checks the authenticated caller against the authoritative row owner, requires private empty/absent access control and the measured empty data/metadata profile, and matches the supplied DTO's ID, user, filename, hash, timestamps, and metadata to the row. Missing and foreign identities receive the same fixed error. No file path is read, no file bytes are opened, and no upload, update, delete, processing, or provider operation occurs. The existing batch database transaction still creates only the chats and rolls back on insert failure.

`python3 validation/test_bulk_chat_import.py` runs 16 source-extracted checks. The seven new test functions cover measured attached-text graph preservation, one DAO lookup for the same identity across multiple chats, no lookup on ordinary file-free imports, nondisclosing missing/foreign refusal, mismatched and late-invalid pre-write refusal, and spoofed/non-text/extra/multiple-reference refusal. Existing no-file, singleton route, bounds, owner/private defaults, nullable behavior, and batch rollback checks also pass. The tests use an isolated SQLite chat table plus a synthetic authoritative file-row stub; they do not open file bytes or qualify the mounted app. `git diff --check` and source/test `py_compile` pass.

Primary retains the actual current profile: one 77-byte private text upload, owner download exact, other user denied with 404, anonymous denied with 401; the same three references occur in the stored graph. A candidate baseline returned 422 before chat creation while legacy singleton import remained successful. This local slice does not prove native HTTP compatibility, actual file reopening through the imported chat, processed/RAG behavior, multiple files, binary/media attachments, group/public grants, cleanup after an earlier upload, exporter bundling, or broader migration/cutover. Primary owns the unchanged-client replay and real DAO/database review.

The user journey is an existing member uploading a small workshop file and importing a conversation that points to it. The direct path preserves existing bytes and owner-only access; unsupported data fails before chat inserts. The DAO stub is a source-level check, not evidence of comprehension, a product UI, or a full saved-file recovery path. No macOS or Windows integration claim is made.
