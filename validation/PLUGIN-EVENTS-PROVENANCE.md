# Plugin event routing compatibility prototype

The primary's measured own async-Pipe journey showed ordered progress on `chat-events`, but a member-supplied foreign session ID received both progress and final reply in the source64 candidate. The measured current 0.12.4 service delivered those events only to the requesting member and ignored the foreign SID; its useful member reply continued. Other acknowledgement/status/task-ID and lifecycle differences are outside this first slice.

`backend/open_webui/socket/main.py:get_event_emitter` now considers only the existing request user's `USER_POOL` SIDs plus the requested SID, and emits only to entries whose existing `SESSION_POOL` record is a dictionary with matching `id`. Invalid or empty request user IDs produce no recipients. It does not query the database or perform auth/credential lookup. The default channel remains one `chat-events` emission per eligible session. When `OPENATELIER_EVENT_CHANNEL_COMPAT=1`, the same envelope is additionally emitted once on `events`; this intentionally duplicates serialization for opt-in comparison. Existing event payloads and `update_db` status/message/replace processing remain unchanged.

Four focused source-extracted tests exercise foreign/stale/malformed session entries, duplicate requested/pool IDs, valid same-user multi-tab routing, invalid user IDs, default-off channel count, opt-in alias envelope identity, and one status DB update. They execute the actual `get_event_emitter` function body with fake in-memory pools, socket emitter, and chat store; they do not import or run the full application or establish Socket.IO transport behavior. Primary owns independent source, default-off, native, and migrated-client replay.

The alias's duplicated event count and serialized size are measured later by the primary native comparison; this source test does not establish the contract's provisional per-completion packet/byte/latency budget. Other socket events, interactive callbacks, cross-process Redis semantics, reconnect/cancellation, HTTP acknowledgements, tasks, final-output payloads, UI delivery, notification, and human comprehension remain unqualified. No durable default, full event security, or general event compatibility claim is made.
