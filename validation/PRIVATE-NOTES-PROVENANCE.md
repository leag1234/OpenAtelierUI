# Private notes compatibility prototype provenance

This is a default-off source prototype for the measured private notes journey. It uses only the retained synthetic observations in `TASK-OPENATELIER-PRIVATE-NOTES-001` and the normalized Note request/response schemas. The unchanged current reference passed the frozen client with 19 calls and 13 scope controls. The old candidate's selected notes paths returned HTML `200` and created no notes. The earlier current-observer null-data normalization and pinned-note masking mistakes were primary-owned and retained separately; they are not candidate implementation results.

`OPENATELIER_PRIVATE_NOTES_COMPAT=1` conditionally imports and registers the router before readiness. Router import prepares only the `openatelier_private_note` table and its owner/time index. With the flag absent, the main module does not import/register the router; an explicit router import also skips storage preparation. Unsupported databases or note-table schemas leave the rest of the application available and make this router return a fixed `503`. The prototype accepts only an existing regular file-backed SQLite database, rejects symlinked paths and schema collisions, and uses short standard-library SQLite transactions with parameterized data operations.

The selected private API surface supports owner-only list/read/create/search/update/pin and pinned-list operations for existing verified `user` and `admin` callers. IDs and ownership come from the server; nonempty grants are refused, and an explicit `workspace.notes=false` or `features.notes=false` in the existing user permission map or a member group refuses access. The user/group permission check is conservative: any explicit group false refuses even if another group might allow an action under the older permissive group-union algorithm. No role, grant, or default is added. Null stored data is returned as `{}`, null metadata remains null, grants are empty, and update retains pin state. Search is literal title matching with bounded paging; unsupported view, permission, and ordering options are refused.

The router reuses the authenticated caller's `id`, `name`, `role`, and `email` for the selected search-result owner projection. It does not query another user's profile. FastAPI synchronous handlers keep SQLite and group permission lookups off the event loop. Requests bound titles to 8 KiB, serialized note JSON to 32 KiB and nesting to 64 levels, with at most 32 notes per page and page numbers through 4096.

Local validation used real temporary SQLite databases and the installed FastAPI/Pydantic models, then called extracted router handlers with controlled auth/group modules. `python3 validation/test_private_notes.py` passes four named tests covering fresh table/index creation, preservation of an unrelated existing row, private CRUD/search/pin/reopen, explicit user/group policy denial, invalid grants/pages/data, unsupported database/schema refusal, default-off table absence, and selected response schemas. `PYTHONPYCACHEPREFIX=/tmp/openatelier-notes-pycache python3 -m py_compile backend/open_webui/models/notes.py backend/open_webui/routers/notes.py backend/open_webui/main.py` and `git diff --check` pass. This is not the primary frozen HTTP replay or a complete application startup qualification; the primary owns those checks.

There is no notes editor or rendered UI change. Sharing, nonempty grants, note history, deletion, note/chat generation, rich-text/editor behavior, general SDK use, PostgreSQL, full notes-domain parity, migration/recovery, and durable storage adoption remain unsupported or unqualified. The index and storage layout are experimental. Search/order defaults beyond the measured literal-title case are not claimed. The fast local test duration is not a latency or idle-resource benchmark. A failed first test invocation exposed Python 3.9 syntax incompatibility from `| None`; annotations were changed to `Optional`. A first `py_compile` invocation was denied while writing bytecode to the macOS framework cache; it passed with the explicit temporary cache above. A direct handler test also initially passed FastAPI's `Query` sentinel instead of the page value; the test now supplies the concrete parameter.
