# Private Notes UI prototype provenance

This source change adds a gated UI for the separately qualified private-notes API. The authenticated `/api/config` response advertises `features.openatelier_private_notes` only when `OPENATELIER_PRIVATE_NOTES_COMPAT=1`; the optional frontend Config field and sidebar link follow that signal. The page is `/notes`. A direct visit while the feature is unavailable shows a clear fallback to chat. No permission is inferred from the flag: the API continues to enforce its owner and explicit-deny checks.

The interface supports a private title and plain text note, save, pin, title search, bounded paging, and reopen. It sends only `{content:{md:TEXT}}`, keeps existing metadata including `null`, and permits editing only empty data or that exact text shape with an empty grants list. Other note data remains escaped read-only JSON with a local JSON download. The editor keeps a failed draft, uses Save/Discard/Keep before switching, and uses browser confirmation for unsaved route/reload exits. Ctrl/Cmd+S invokes the explicit Save action. API errors are reduced to fixed user-facing messages; note bodies are not logged or rendered as HTML.

The added own component has 215 nonblank lines, the Notes API wrapper 27, pure state helper 48, and the route page 4. Sidebar adds 9 nonblank lines, the Config type adds 1, and backend config projection adds 1. `validation/test_private_notes_ui.mjs` has four named Node tests for supported/opaque data shapes, dirty state, metadata-preserving text payloads, and failed-save draft retention. `node --test validation/test_private_notes_ui.mjs` passes; the existing `python3 validation/test_private_notes.py` still passes all four backend tests. These are local state/store tests, not browser or rendering validation.

The primary owns compiled-build, HTTP integration, actual desktop/mobile rendering, keyboard, and saved-work review. No claim of usability is made before those checks. Rich editing, sharing, deletion, history, collaboration, offline local persistence, and general notes SDK behavior remain outside this prototype. Existing playground scratch notes, other routes, theme/icon assets, dependencies, and storage/auth models are unchanged. The implementation adds no polling or client persistence and uses the existing Notes icon, theme, and authenticated API conventions.
