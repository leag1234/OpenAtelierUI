# Private Notes UI prototype provenance

This source change adds a gated UI for the separately qualified private-notes API. The authenticated `/api/config` response advertises `features.openatelier_private_notes` only when `OPENATELIER_PRIVATE_NOTES_COMPAT=1`; the optional frontend Config field and sidebar link follow that signal. The page is `/notes`. A direct visit while the feature is unavailable shows a clear fallback to chat. No permission is inferred from the flag: the API continues to enforce its owner and explicit-deny checks.

The interface supports a private title and plain text note, save, pin, title search, bounded paging, and reopen. It permits editing only empty data or `{content:{md:TEXT}}` with an empty grants list. Other note data remains read-only and can be downloaded as JSON. The editor keeps a failed draft, uses Save/Discard/Keep before switching, and uses browser confirmation for unsaved route/reload exits. Ctrl/Cmd+S invokes the explicit Save action. API errors are reduced to fixed user-facing messages; note bodies are not logged or rendered as HTML.

The added own component has 275 nonblank lines, the Notes API wrapper 27, pure state helper 59, and the route page 4. Sidebar adds 9 nonblank lines, the Config type adds 1, and backend config projection adds 1. `validation/test_private_notes_ui.mjs` now has nine named Node tests, including selective update payloads and exact raw-response retention. Run it with the bundled Node 24 executable using `node --test validation/test_private_notes_ui.mjs`; the default shell `node` does not provide `--test`. `validation/test_private_notes.py` now passes six backend tests, including atomic merged-size refusal and exact preservation of ignored raw columns. These are local state/store tests, not browser or rendering validation.

Before primary staging, review identified a possible stale GET overwriting a draft and concurrent pin toggles. The page now locks note-changing actions and inputs while a detail GET, save, or pin request is pending; detail responses also retain the selection-generation check. A successful save reports separately if list refresh fails, and unsupported data is described without displaying raw JSON by default (download remains explicit). The pending-action dialog cannot discard or retarget a draft during an in-flight save. Browser-dependent setup and cleanup are guarded for server rendering, and the page adds an existing-store mobile sidebar control. These are source-level corrections; browser timing and visual behavior remain unqualified until primary integration review.

A newly opened blank note now says “Not saved yet”; the “Saved” label is reserved for persisted notes.

Primary's rendered desktop review found that the prior centered maximum-width container left a large blank region and compressed the editor. The page now follows the existing responsive app-layout width pattern, fills its available width without a centering cap, constrains the main region to the viewport with vertical scrolling, and exposes the existing sidebar toggle on desktop when the sidebar is closed (and on mobile). This source correction has not yet received a new compiled or rendered review.

The native keyboard review found focus remained behind the unsaved-changes prompt. Opening the prompt now focuses “Keep editing,” traps Tab and Shift+Tab within the prompt, returns focus to its trigger when dismissed, and closes on Escape without discarding the draft. Escape remains blocked while a save/pin/open request is in flight. A pure helper test covers focus wrap boundaries; actual browser keyboard behavior remains for primary verification.

The note list formats only the two measured timestamp forms: current nanoseconds and historical prototype seconds. Unsupported values, including milliseconds, display “Unknown date”; no other timestamp-unit conversion is claimed. Creation and updates use the measured nanosecond clock, while existing stored second values remain unchanged.

Existing-note updates send only the fields the user changed: title-only saves omit `data` and `meta`, and text edits send only the plain-text `data` object. This lets the server retain opaque metadata and large integer values exactly; new-note creation keeps its existing `meta: null` request. For notes returned by get/create/update, the API wrapper retains the bounded original response JSON text in a `WeakMap` keyed by the parsed object. “Download note JSON” uses that exact text through the repository's existing `file-saver` helper and never reconstructs it with `JSON.stringify`; if the original response is unavailable, the UI asks the user to reopen the note. The 65,536-byte retention bound and state tests cover exact 19-digit values and the missing-raw fallback. This is source-level behavior only; an actual browser download remains unverified.

The primary owns compiled-build, HTTP integration, actual desktop/mobile rendering, keyboard, and saved-work review. No claim of usability is made before those checks. Rich editing, sharing, deletion, history, collaboration, offline local persistence, and general notes SDK behavior remain outside this prototype. Existing playground scratch notes, other routes, theme/icon assets, dependencies, and storage/auth models are unchanged. The implementation adds no polling or client persistence and uses the existing Notes icon, theme, and authenticated API conventions.
