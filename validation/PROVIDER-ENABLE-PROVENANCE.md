# Per-endpoint provider enable-state import

This follow-up preserves the measured `openai.api_configs` setting in the existing default-off `--include-openai-configuration` import. The own current 0.12.4 and source63 native profiles matched on nine selected calls for two indexed endpoints with explicit false/true enable states: the disabled model remained absent and its direct attempt returned 400 without provider traffic; the enabled model completed successfully in plain and SSE modes using only the second endpoint. Existing scope, key, anonymous-denial, and routing checks passed. These observations qualify this exact two-endpoint fixture only.

The importer now accepts either the previously supported empty options object or a complete map for every canonical string index from `"0"` through `str(endpoint_count - 1)`. Each entry must be an object with exactly one field, `enable`, whose value is a strict JSON boolean. Values and indices are preserved without coercion. Sparse maps, out-of-range or zero-padded aliases, unknown fields, extra per-endpoint settings, non-object entries, and non-boolean values are refused before target creation. Existing default-off behavior, flags, report fields, selectors, schema, and cutover blockers remain unchanged; no runtime/provider code or defaults changed.

The earlier importer safely refused all nonempty endpoint options. This follow-up narrows that refusal to unmeasured shapes and preserves the newly measured enable-only map. Local tests assert exact false/true conversion and pre-target refusal for sparse, alias, out-of-range, extra-field, wrong-type, and wrong-container forms, while prior empty-options and multi-endpoint tests remain. Primary still owns independent CLI/migration/native replay; this source change alone does not establish integrated migration acceptance or support for arbitrary endpoint counts/options.
