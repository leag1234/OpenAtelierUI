# Default-off copied-profile session auth integration provenance

This is the bounded prototype authorized by `TASK-OPENATELIER-SESSION-AUTH-001`. It depends on the inactive copy-only SQLite component in `utils/session_epochs.py`. The environment switch `OPENATELIER_SESSION_EPOCHS` is disabled unless its value is one of `1`, `true`, `yes`, or `on` (case-insensitive). When disabled, token payloads and current-user lookup follow the pre-existing path. The code adds no ORM field, automatic schema change, importer behavior, dependency, cache, or default activation.

When enabled, token creation copies the caller payload, keeps existing expiration construction, and adds a trusted `session_stamp` plus a fresh UUID `jti` using the existing secret and HS256 algorithm. A current-user request keeps the existing bearer-over-cookie choice and API-key branch. For JWTs, it performs existing decode/signature/expiry validation first, rejects a missing or malformed stamp as `401 Invalid token`, then compares the stamp to the existing file-backed SQLite auth row before loading the user. Unsupported database URLs and unavailable, malformed, busy, or unprepared storage become a generic `503 Session state unavailable`; no database details are returned. The environment must provide an absolute file-backed SQLite URL (`sqlite:///` or `sqlite+driver:///`); relative, memory, non-SQLite, query, and fragment forms are unsupported. Path characters are preserved literally when deriving the SQLite filename, including `%20`.

`POST /api/v1/auths/signout` delegates to the existing GET handler, including its cookie/OAuth response path; it does not rotate account state. The admin-protected `POST /api/v1/users/{user_id}/sessions/revoke` rotates one existing account only when the experiment is enabled. Missing targets map to HTTP 404 with `{"detail":"User not found."}`; disabled or unavailable state maps to the generic 503. Existing administrator authorization remains the route dependency.

The source-bound checks run with:

```sh
PYTHONPYCACHEPREFIX=/tmp/bsd-epochs-pycache python3 backend/open_webui/test/test_session_epoch_auth.py
PYTHONPYCACHEPREFIX=/tmp/bsd-epochs-pycache python3 backend/open_webui/test/test_auth_missing_credentials.py
PYTHONPYCACHEPREFIX=/tmp/bsd-epochs-pycache python3 backend/open_webui/test/test_session_epochs.py
```

The primary's review of initial commit `8d3d185` arrived just after it was created and identified three issues before runtime staging: the measured missing-target body needs the exact `{"detail":"User not found."}` text, literal percent characters must remain unchanged in SQLite filenames, and the POSIX `resource` import must be limited to the measurement helper. These were corrected separately before runtime review. The first `%20` test run hit a fixture naming collision because its builder reused the prior temporary source filename; the builder now derives a unique source filename per target and the full suite passed. Moving the import keeps default-off authentication imports independent of the POSIX-only measurement module.

`test_session_epoch_auth.py` extracts the checked-in functions and route handlers from the actual source and supplies controlled users, request objects, a JWT stub, and the actual SQLite component. It checks default-off payload and user lookup, enabled payload nonmutation, preserved expiry field construction, stable epoch/fresh `jti`, decode-before-epoch-before-user ordering, stale/missing/malformed claims, deleted-auth-row status, malformed/busy store refusal and recovery, literal-percent filenames, unsupported database URL refusal, lazy measurement-only `resource` import, admin dependency and target errors, API-key separation, signout delegation, and source route paths. The final corrected local run passed 14 named integration cases (0.256s), the existing `test_auth_missing_credentials.py` run passed 5 controls (0.010s), and the actual SQLite `test_session_epochs.py` run passed 13 cases (0.201s). `git diff --check` passed. `test_auth_missing_credentials.py` retains the existing bearer/cookie/API-key controls. `test_session_epochs.py` tests the actual stdlib SQLite component.

These source-extracted tests do not exercise the full FastAPI dependency graph, actual JWT library signing/verification, real ORM connection/pool behavior, mounted application routes, OAuth-provider responses, or browser clients. The helper host lacks SQLAlchemy, so this integration was not imported as a complete app and no dependency was installed. The only SQL persistence tests use Python's real SQLite library on synthetic copies. The primary owns actual existing-image HTTP and restart tests. No current/upstream source, real token, credential, full auth/config/session row, or production database was used by the helper. This commit does not establish full current JWT DTO/MFA/config compatibility, API-key revocation, ongoing stream termination, backup rollback safety, Postgres support, user comprehension, notification delivery, or a durable schema/storage decision.
