# Default-off copied-profile session auth integration provenance

This is the bounded prototype authorized by `TASK-OPENATELIER-SESSION-AUTH-001`. It depends on the inactive copy-only SQLite component in `utils/session_epochs.py`. The environment switch `OPENATELIER_SESSION_EPOCHS` is disabled unless its value is one of `1`, `true`, `yes`, or `on` (case-insensitive). When disabled, token payloads and current-user lookup follow the pre-existing path. The code adds no ORM field, automatic schema change, importer behavior, dependency, cache, or default activation.

When enabled, token creation copies the caller payload, keeps existing expiration construction, and adds a trusted `session_stamp` plus a fresh UUID `jti` using the existing secret and HS256 algorithm. A current-user request keeps the existing bearer-over-cookie choice and API-key branch. For JWTs, it performs existing decode/signature/expiry validation first, rejects a missing or malformed stamp as `401 Invalid token`, then compares the stamp to the existing file-backed SQLite auth row before loading the user. Unsupported database URLs and unavailable, malformed, busy, or unprepared storage become a generic `503 Session state unavailable`; no database details are returned. The environment must provide an absolute file-backed SQLite URL (`sqlite:///` or `sqlite+driver:///`); relative, memory, non-SQLite, query, and fragment forms are unsupported. Path characters are preserved literally when deriving the SQLite filename, including `%20`.

`POST /api/v1/auths/signout` delegates to the existing GET handler, including its cookie/OAuth response path; it does not rotate account state. The admin-protected `POST /api/v1/users/{user_id}/sessions/revoke` rotates one existing account only when the experiment is enabled. Missing targets map to HTTP 404 with `{"detail":"User not found."}`; disabled or unavailable state maps to the generic 503. Existing administrator authorization remains the route dependency.

## Guarded renewal correction

The read-only source-extracted check reproduced an in-flight ordering: `get_current_user` validates an old JWT, an administrator rotates the account epoch, and the already-admitted `GET /api/v1/auths/` route then calls `create_token` using only the user ID. That path could issue a JWT with the newly rotated epoch. The correction carries a private server-side request marker only after the JWT signature/expiry and trusted epoch checks succeed. The renewal route supplies that exact validated stamp to `create_token`; `issue_epoch` compares it to the stored stamp under its existing `BEGIN IMMEDIATE` transaction and refuses a mismatch without initializing or writing. A rotation after the guarded issue can still make the returned token immediately stale, which remains closed behavior. Initial sign-in keeps the normal issue path, and API-key/custom dependency paths receive no validated-JWT marker. The default-off route remains unchanged.

New epoch-state refusals use the measured literal `Invalid token`. This is deliberately separate from the legacy `ERROR_MESSAGES.INVALID_TOKEN` text (`Your session has expired or the token is invalid. Please sign in again.`), which must remain in pre-existing default-off paths. The source34 38-call comparison is retained: it had 297 checks with 8 failures, 7 selected effect differences, and 14 additional DTO-key gaps. The primary's first test stub used `Invalid token` for the legacy constant, masking this response-copy distinction; the helper stub now uses the distinct measured legacy value and tests the new epoch refusals separately. The source34 replay and its other gaps remain primary-owned evidence; this correction does not claim that the candidate now passes that replay.

The new local check extracts the actual component, auth functions, and `GET /auths` route, uses a temporary SQLite copy and test JWT stub, and checks both deterministic orderings. Rotation before renewal yields `401 Invalid token`, no JWT encode, no epoch write or cookie, and an old token remains rejected; a post-rotation fresh login works. Renewal before rotation carries the original validated stamp, works while current, and becomes invalid if rotation follows. The final local run passed 16 component tests (0.795s), 17 auth-integration tests (0.442s), and 5 existing auth controls (0.011s); syntax compilation with `PYTHONPYCACHEPREFIX=/tmp/bsd-epochs-pycache` and `git diff --check` passed. An earlier route test stopped because the synthetic user lacked response fields; the fixture was completed and the full suite then passed. A direct `python -m py_compile` attempt also stopped before compilation when Python tried to create its default cache under the protected macOS Library path; the prefixed compilation and named tests then passed. These source-extracted results do not qualify installed PyJWT, live request scheduling, mounted application behavior, or a general race rate; primary owns those checks and final interpretation.
